# Afterimage Diary · версия 2

Личный дневник, который сохраняет не только то, что произошло, но и то, каким был день:
рассказ, фотографии, место, погода и музыка превращаются в оформленную запись.

В проекте нет внешних пакетов: ни `npm install`, ни сборщиков. Нужны только браузер и,
для входа по почте и паролю, Node.js 22.5 или новее.

## Три способа запуска

| Способ | Как запустить | Аккаунт | Где хранятся записи | ИИ |
|---|---|---|---|---|
| **В Claude** | открыть опубликованную страницу | аккаунт Claude (отдельной регистрации нет) | приватный раздел хранилища страницы | Claude, настоящий |
| **Свой сервер** | `cd server && node server.js --dev` → http://localhost:3000 | регистрация по почте и паролю | SQLite и файлы на сервере | через сервер, если задан ключ |
| **Один файл** | открыть `dist/standalone.html` двойным щелчком | нет | только этот браузер (IndexedDB) | демо-движок, подписан как не ИИ |

Страница сама определяет, где она открыта, и честно показывает режим в шапке, в настройках и на каждой записи.

### Свой сервер

```bash
cd server
node server.js --dev          # режим разработки: http://localhost:3000
npm test                      # 91 проверка сервера, внешние сервисы заменены локальной заглушкой
```

Рабочий режим включён по умолчанию и не стартует с небезопасными настройками:

```bash
PUBLIC_URL=https://diary.example.com node server.js      # за HTTPS-прокси; при необходимости TRUST_PROXY=1
node --env-file=.env server.js                           # то же, если настройки лежат в файле .env
```

Список переменных с пояснениями — в `server/.env.example`. Данные лежат в `server/data`
(база `afterimage.db` и папка `blobs`); для резервной копии достаточно скопировать эту папку.

### После правок в исходниках

```bash
./build.sh
```

Скрипт собирает из `web/src` три варианта: `dist/afterimage.html` (страница для Claude),
`dist/standalone.html` (отдельный файл) и `server/public/*` (код и стили отдельными файлами,
потому что сервер запрещает встроенные скрипты).

## Что реализовано

- **Русский интерфейс** целиком, название Afterimage сохранено.
- **Меню** из восьми разделов с обводкой, активным состоянием, выделенным «Новым воспоминанием»,
  короткой анимацией наведения, состоянием нажатия для касаний, видимым фокусом и учётом
  `prefers-reduced-motion`. На телефоне меню сворачивается в кнопку.
- **Аккаунт** (свой сервер): регистрация, вход, выход, восстановление и смена пароля, удаление
  аккаунта. В Claude роль аккаунта выполняет аккаунт Claude, и страница так и говорит.
- **Перенос локальных записей** в аккаунт: список и объём до загрузки, явное подтверждение,
  локальные копии не удаляются.
- **ИИ-оформление**: три варианта с предпросмотром и объяснением; обложка и порядок кадров,
  палитра, шрифты, шаблон, фактура, эффект, движение; всё можно поправить вручную.
  Ползунок цветовой температуры меняет только цвет и не трогает погоду в записи.
- **Шаблоны**: Фотоплёнка, Открытка из поездки, Страница дневника, Коллаж настроения
  (плюс Афиша, Снимки на столе, Окно). Миниатюры собираются из ваших фотографий.
  Кадрирование точкой и приближением, подписи, порядок перетаскиванием или кнопками.
- **Музыка**: ссылка (сервис определяется, официальный плеер — по нажатию и только на своём сайте),
  название вручную, подбор направлений по настроению, собственный аудиофайл. Ничего не играет само.
- **Идеи в Pinterest**: кнопка открывает поиск по палитре и настроению на сайте Pinterest.
- **Дневник**: список, календарь, фотоплёнка; поиск по тексту, дате, месту, песне и меткам;
  фильтры по году, настроению, погоде и месту; изменение и удаление с подтверждением.
- **В этот день**, **Коллекции** (лента-фотоплёнка, обложка, запись в нескольких коллекциях),
  **Карта** (метки, объединение близких, маршрут коллекции по датам).
- **Профиль** и **Настройки**: тема, фактический режим ИИ и его выключатель, передача фотографий ИИ,
  описание хранения, резервная копия одним zip-файлом, очистка данных и удаление аккаунта.
- **Живой фон** на CSS: медленные пятна и зерно, неподвижные при уменьшенном движении.
- **Записи первой версии** открываются как раньше, их старые шаблоны сохранены.

## Что требует ключей или настройки

| Возможность | Что нужно | Без этого |
|---|---|---|
| ИИ на своём сервере | `ANTHROPIC_API_KEY` в окружении сервера (в браузер не попадает). Модель — `AI_MODEL` | демо-движок по ключевым словам, везде подписан |
| Фотографии для ИИ на сервере | `AI_SEND_PHOTOS=1` | ИИ получает только текст и измеренные цвета |
| Поиск адресов на сервере | `GEOCODER_CONTACT=ваша@почта` (OpenStreetMap Nominatim, ключ не нужен) | метка ставится вручную на карте |
| Письма для сброса пароля | `MAIL_WEBHOOK_URL` (+ `MAIL_WEBHOOK_TOKEN`): адрес, принимающий `POST {to, subject, text}` | в режиме разработки ссылка печатается в консоль сервера; в рабочем режиме сброс недоступен |
| Рабочий запуск | домен с HTTPS и `PUBLIC_URL` | только `--dev` на своём компьютере |
| Интеграция с Pinterest | приложение разработчика Pinterest, OAuth и токен на сервере | ссылка на поиск Pinterest в новой вкладке |
| Каталог музыки | API музыкального сервиса и его ключи на сервере | ИИ предлагает направления, а не песни; ссылки ведут на поиск в сервисах |
| Карта с улицами и городами | картографический сервис с плитками и его ключ | схематичная карта суши, нарисованная для проекта |

### Как подключить то, что оставлено заготовкой

**Почта.** `sendMail()` в `server/server.js` отправляет `POST` с JSON `{ to, subject, text }` и
заголовком `Authorization: Bearer <MAIL_WEBHOOK_TOKEN>`. Подойдёт HTTP-API любого почтового
сервиса или маленькая функция, которая пересылает письмо через SMTP.

**Pinterest.** Сейчас `pinterestBlock()` в `web/src/js/08-music.js` строит обычную ссылку на поиск.
Для настоящей интеграции: зарегистрировать приложение в кабинете разработчика Pinterest,
пройти OAuth, хранить токен на сервере, добавить серверный адрес вроде `GET /api/pins?q=…`
и показывать результаты ссылками на оригиналы. Точные адреса и права API сверяйте с актуальной
документацией Pinterest; изображения в дневник копировать не нужно.

**Каталог музыки.** `suggestMusic()` в `web/src/js/04-ai.js` возвращает направления. Чтобы
предлагать конкретные треки, добавьте серверный адрес, который ищет по строке `query` в API
выбранного сервиса (ключ остаётся на сервере), и показывайте только то, что сервис действительно вернул.

**Карта.** `createMap()` в `web/src/js/07-map.js` рисует собственную схему. Чтобы заменить её
плитками, понадобится картографический сервис, его условия использования и, как правило, ключ;
источник плиток нужно будет разрешить в `Content-Security-Policy` сервера.

## Безопасность сервера

- Пароли: scrypt с отдельной солью, в базе только хеш. Сессия: случайный токен в cookie
  `HttpOnly; SameSite=Strict` (в рабочем режиме `__Host-` и `Secure`), в базе только его SHA-256.
- Защита от подделки запросов: собственный заголовок, точное совпадение `Origin`, проверка `Host`; CORS закрыт.
- Каждый запрос к записям и файлам отбирает их по владельцу сессии; чужой файл неотличим от несуществующего (404).
- Ограничения (уникальность почты, одноразовая ссылка сброса, квота файлов, лимит обращений к ИИ,
  попытки входа) выполняются одним запросом к базе, поэтому параллельные запросы их не обходят.
- Тип файла определяется по содержимому, имя придумывает сервер, размер ограничен.
- Запрос к ИИ собирает сервер из проверенных полей; рассказ вставляется как данные между маркерами.
- Строгая `Content-Security-Policy` без встроенных скриптов и стилей, `nosniff`, HSTS в рабочем режиме.

Чего нет и что стоит добавить перед публичным запуском: подтверждение почты письмом,
двухфакторный вход, резервное копирование по расписанию.

## Что проверено, а что нет

Проверено автоматически: сервер (`npm test`), полный путь в браузере в трёх режимах
(регистрация, вход и выход, запись с несколькими фотографиями и коллажем, старые записи,
музыка, коллекции, карта, профиль, настройки, перенос, резервная копия), ширина 320, 390 и 768
пикселей, клавиатура, анимация меню, уменьшение движения.

Не проверено на настоящих сервисах, только на локальных заглушках: живой ответ Claude,
настоящий ключ Anthropic API, настоящий Nominatim, настоящая отправка писем.
